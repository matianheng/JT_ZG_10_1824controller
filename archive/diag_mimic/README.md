# diag_mimic —— 仿原厂形态诊断固件（排查 Bootloader 镜像验收）

把 `scan_test`（45 脚输出轮扫）和 `can_trigger_test`（CAN 发送 + ADC 扫描）
合并成一版固件，**刷一次同时验证三条链路**，不用再轮流刷机。
仍是台架诊断固件，不是正式 Demo。

## 本版与 diag_test v2 的三点差异（其余全部相同）

底本是 diag_test v2：PA15 上电置高保持、45 脚轮扫、CAN 0x7A0/0x7A1/0x7A2、
ADC 全扫描、CAN 初始化 HAL 顺序与超时，**一点没动**。只改三处，目的都是
让自研镜像在“形态”上向原厂 dl1824.bin 靠拢，排查 Bootloader 是否按
栈值/大小之类条件验收镜像：

1. **栈顶对齐原厂**：链接脚本 `_estack` 由 0x20020000 改为 **0x20006538**，
   与原厂 dl1824.bin 向量表第一个字（初始栈值）完全一致；
   FLASH 起始仍为 0x08010000。构建后自检头 8 字节应为 `38 65 00 20` 开头。
2. **产物填充至 189,551 字节**：build.sh 在生成 dl1824.bin 后自动用 0xFF
   把文件补到与原厂 dl1824.bin **完全相同的大小**（原产物约 2.1K，头部
   内容不变；若产物已超长则直接报错）。自检输出后会打印填充后的文件大小，
   应为 189551 字节。
3. **PA12 心跳改为“双闪”节律**：亮 100ms → 灭 100ms → 亮 100ms →
   灭 1700ms，周期 2000ms 循环。原厂 run 灯是常亮、diag_test v2 是
   2Hz 均匀翻转，本版的双闪与两者都不会混淆。

## 怎么判读（刷完只看 run 灯）

- **run 灯呈双闪节律**（闪-闪-停、闪-闪-停……）→ 自研固件**确实在跑**，
  且本版镜像被 Bootloader 接受。之前几版“没反应”更可能是镜像形态
  （栈值/大小）不满足验收，或观察被常亮掩盖——后续正式固件沿用本版的
  栈值与填充做法即可。
- **run 灯仍常亮**（和刷原厂源程序时一样）→ 本版镜像仍未运行，
  验收条件不在栈值/大小这两项上，继续排查其它验收条件（如校验和、
  特定偏移的魔数、工具写入方式），不要再改功能代码。

## 构建与刷写

同其它工程：本目录 `./build.sh`（先 `chmod +x build.sh`），产物
`build/dl1824.bin`（基址 0x08010000），用原来的方式刷进备用板。
**仅限台架、连接器上只接灯与电位器、无阀类负载时使用。**

## 一次刷机验证什么

### (a) CAN 链路 —— 上电即有，不依赖任何输入

固件一运行就以 **250ms 周期无条件发送状态帧 0x7A0**。
监听工具只要收到 0x7A0，就一次性证明：固件在跑、时钟在走、
CAN1（J3-1/2，线号 113/114）物理链路与波特率都通。
**如果连 0x7A0 都没有，问题在刷写/供电/CAN 接线这一层，先别怀疑
AI 和灯。**

### (b) 灯脚 —— 轮扫步号不用数闪烁

45 个候选输出脚逐个置高、每步 1 秒循环轮扫；每轮开始全部脚
齐闪 3 次作标记（同 scan_test）。**当前步号随 0x7A0 的字节 5
一起发出**（0 = 正在齐闪标记，1–45 = 步号）：盯着监听软件看
字节 5，灯亮时记下那个数，查下方对照表即知是哪只芯片脚——
驱动 J1-17 的脚就是它。

### (c) AI 通路 —— 看哪一路跟旋钮动

固件每轮做 8 个多路复用槽 × 12 路 ADC 通道的全扫描：

- 任意一路原始值 ≥ 2048（半量程，对应台架刻度 12V 的假定阈值）
  时发 **0x7A1**，内含最大值、所在槽号与通道编码；
- 每秒发一组 **0x7A2**（4 帧），装 12 路通道在槽 0 的原始值。

拧电位器时，盯 0x7A2 哪一路数值跟动（或看 0x7A1 的槽号/通道
编码），那一路就是 J1-1 的真实通路；同时记下万用表 12.0V 时
的原始值，可用于标定准确阈值。

## 帧格式（均为标准帧，8 字节）

### 0x7A0 状态帧（每 250ms，无条件）

| 字节 | 含义 |
|---|---|
| 0–3 | 毫秒计数低 32 位（小端，近似值） |
| 4 | 滚动计数（每发一帧 +1，与 0x7A1/0x7A2 共用） |
| 5 | 当前扫描步号：0 = 齐闪标记阶段，1–45 = 步号 |
| 6–7 | 本轮 ADC 最大原始值（小端，0–4095） |

### 0x7A1 触发帧（最大值 ≥ 2048 时，每轮一帧）

| 字节 | 含义 |
|---|---|
| 0–1 | 最大原始计数（小端，0–4095） |
| 2 | 最大值所在多路复用槽号（0–7） |
| 3 | 通道编码：高 4 位 ADC 号（0=ADC1，1=ADC2，2=ADC3），如 0x1C = ADC2 的 IN12 |
| 4 | 本轮过阈值的读数个数 |
| 5 | 滚动计数 |
| 6–7 | 按 24V 满量程换算的电压×100（小端，如 1200 → 12.00V） |

### 0x7A2 原始值组帧（每秒一组，共 4 帧）

每帧装 3 路通道在槽 0 的原始值（各 2 字节小端），通道顺序同下表；
字节 6 = 帧序号（0–3），字节 7 = 滚动计数。

| 帧序号 | 字节 0–1 | 字节 2–3 | 字节 4–5 |
|---|---|---|---|
| 0 | 通道 0 | 通道 1 | 通道 2 |
| 1 | 通道 3 | 通道 4 | 通道 5 |
| 2 | 通道 6 | 通道 7 | 通道 8 |
| 3 | 通道 9 | 通道 10 | 通道 11 |

12 路通道表（序号 = 上表“通道 n”）：

| 序号 | ADC 通道 | 芯片脚 | 编码 | 备注 |
|---|---|---|---|---|
| 0 | ADC1 IN13 | PC3 | 0x0D | |
| 1 | ADC1 IN6 | PA6 | 0x06 | |
| 2 | ADC1 IN15 | PC5 | 0x0F | |
| 3 | ADC1 IN8 | PB0 | 0x08 | |
| 4 | ADC1 IN9 | PB1 | 0x09 | |
| 5 | ADC1 IN7 | PA7 | 0x07 | |
| 6 | ADC1 IN4 | PA4 | 0x04 | 原厂配模拟未采样（备用嫌疑） |
| 7 | ADC1 IN5 | PA5 | 0x05 | 原厂配模拟未采样（备用嫌疑） |
| 8 | ADC2 IN14 | PC4 | 0x1E | |
| 9 | ADC2 IN12 | PC2 | 0x1C | 压力通道（槽 0=P1、槽 6=P2） |
| 10 | ADC3 IN11 | PC1 | 0x2B | |
| 11 | ADC3 IN10 | PC0 | 0x2A | |

注：多路复用通道只在自己的槽里有信号——若 J1-1 在某个非 0 槽，
0x7A2（只报槽 0）里看不到它跟动，要靠 0x7A1 的槽号/最大值定位；
直连通道（如 PA4/PA5）则在每个槽数值相同，0x7A2 能直接看到。

## 监听注意事项

- 波特率 **250 kbit/s**，标准帧；CAN 线接 J3-1（CANH，113）/
  J3-2（CANL，114）。
- ⚠️ 监听工具必须开**正常模式**（参与 ACK）。只听/静默模式下
  无人应答，控制器会不停重发并最终停发，看起来像“没报文”。
- 本固件所有等待都带超时：CAN/ADC 异常不会让固件挂死，0x7A0
  停发即说明固件或时钟层出问题，而不是某个外设没响应。

## 与源工程的差异（合并时的修正）

- CAN 初始化改为 HAL 顺序：先清 SLEEP 等 SLAK 清零，再置 INRQ
  等 INAK（can_trigger_test 原为先 INRQ 后清 SLEEP）；
- adc_read 的 EOC 等待、can_send 的邮箱等待、CAN 初始化应答
  等待全部加计数超时（100000 次），发送失败不阻塞主循环；
- 0x7A0 由 can_trigger_test 的 1 秒心跳改为 250ms 无条件状态帧，
  并带上毫秒计数、扫描步号与 ADC 最大值；
- 输出轮扫由阻塞式延时改为按毫秒状态机推进，与 CAN/ADC 并行，
  每步严格 1 秒（scan_test 原为亮 1 秒 + 灭 250ms）。

## v2 改动（2026-11-11）

- **PA15 上电即置高并保持**：原厂固件对 PA15 有专用置位封装、初始电平为高，疑为
  输出级使能。若 v1 刷后所有输出脚在连接器侧都无动静，可能是输出级根本没使能；
  v2 置高后重看轮扫。若 J1-17 恰好走 PA15 路径，本版下灯会**常亮**（这也是定位信息）。
- **PA12 以 2Hz 翻转**（注：diag_mimic 已改为双闪节律，见文首三点差异第 3 条）：原厂对 PA12 有专用翻转封装，疑为运行灯。若板上 run 灯
  在本版下开始闪烁，即证明自研固件确实在运行（与 CAN/灯路故障分离定性）。

## mimic v2（2026-11-11）：上电时钟归一化

台架实证：mimic v1 刷后 run 灯出现双闪节律（自研固件首次被执行），但节律明显
快于设计的 2 秒周期——判断 Bootloader 跳转时留下了原厂的高速时钟树（PLL，
疑 168MHz），本固件按 16MHz 设的 SysTick 节拍被成比例压缩（CAN 波特率同理偏高）。
v2 在 main 开头调用 clock_force_hsi16()：切 SYSCLK 回 HSI、关 PLL、清 APB 预分频，
之后所有时序（灯步 1 秒、双闪 2 秒周期、CAN 250K）与设计常数一致。
判读：刷 v2 后双闪应回到 2 秒周期；随后灯轮扫与 CAN 0x7A0/0x7A1/0x7A2 才可按
README 前文的表格正式读数。

## mimic v3（2026-11-11）：全矩阵轮发 + 总线自恢复

背景：台架现象为最大值（槽 2/PC2，4056）不随电位器变化，单看最大值无法分辨
“旋钮通路不在最大值处”还是“该读数是钉死的浮置值”。v3 两处改动：

1. **0x7A2 改为 8 槽轮发**：每秒发一个槽的 12 路原始值（4 帧），8 秒轮完
   8 槽 × 12 路全矩阵；字节 6 = 高半字节槽号 | 低半字节帧序号（0x00~0x73）。
   慢慢拧旋钮数轮，看矩阵里哪个（槽，通道）格子跟着动，即 J1-1 的真实通路。
2. **Bus-Off 自恢复 + IWDG 喂狗**：监听工具插拔/掉线期间发送端可能进入
   Bus-Off（默认不自恢复、总线永久沉默），现每圈检测 ESR.BOFF 并重初始化；
   主循环每圈写 IWDG 喂狗寄存器，防止 Bootloader 若开启看门狗导致周期复位。

## mimic v4（2026-11-11）：采样拉满

背景：电位器先后接 J1-1、J1-12（原厂在用压力脚），全矩阵 96 格均无反应，
而板内低阻节点（约 3004/3010/1567 等）读数稳定——需排除固件采样侧嫌疑。
v4：ADC 采样时间全部拉满 480 周期、每通道连转两次弃第一次（去切换残留）、
选槽稳定时间 100→1000µs。刷后重复同一注入测试，若仍无反应，则信号未达
模拟前端（接线/地参考/连接器），与固件无关。
