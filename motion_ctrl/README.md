# motion_ctrl v1 — DL-IO1824G 动作控制固件（草稿，本地准备用，未推仓库）

一句话行为：主令开关闭合才给主控阀供电；变幅模式只通起幅/落幅阀，伸缩模式只通伸/缩臂阀；过卷（CAN ID 192）或 ID 192 超时时切断落幅阀与伸臂阀；超载切断已实现但默认关闭。

**v1 状态：动作版（2026-11-12 两个 DI 均已定位，不再是 HUNT 版）。** 主令 J1-6 = slot 1、ch 9；模式 J1-10 = slot 3、ch 9（均已填入 `src/main.c` 顶部）。刷入后 0x7A0 字节 5 基值应为 `0x25`（动作模式），不再是 `0xA5`。

## 阀脚映射（2026-11-12 实车 diag_mimic 轮扫实测）

| 针脚 | 功能 | 线号 | 步号（45 脚 kPins 表 1-based） | 芯片脚 |
|---|---|---|---|---|
| J1-2 | 主控阀 | 51 | 26 | PC15 |
| J1-4 | 起幅阀（抬臂） | 135 | 18 | PB14 |
| J1-5 | 落幅阀（趴臂） | 64 | 28 | PD3 |
| J1-18 | 伸臂阀 | 62 | 24 | PC13 |
| J1-21 | 缩臂阀 | 63 | 12 | PB6 |

J1-2 由用户 2026-11-12 11:59 再确认（24V 对应 0x1A=26）。**绝不驱动 J1-3**（油路切换阀，本车未接线）。

## 动作逻辑（厂家《输入输出逻辑---初版》文件 03，已与电气原理图核对）

方向由液压先导手柄给，模块只做使能/互锁（阀得电 = 允许该方向动作）：

| 输出 | 得电条件 | 失电（切断）条件 |
|---|---|---|
| 主控阀 J1-2 | 主令 J1-6 闭合 | 主令断开 |
| 起幅阀 J1-4 | 主令 ON 且变幅模式（J1-10 低） | 主令断开；切伸缩模式 |
| 落幅阀 J1-5 | 主令 ON 且变幅模式 | 主令断开；切伸缩模式；过卷；ID 192 超时 |
| 伸臂阀 J1-18 | 主令 ON 且伸缩模式（J1-10 高） | 主令断开；切变幅模式；过卷；ID 192 超时 |
| 缩臂阀 J1-21 | 主令 ON 且伸缩模式 | 主令断开；切变幅模式 |

- **过卷切断（文件 03 范围）**：主钩或副钩任一过卷 → 切 J1-5 + J1-18。起幅阀 J1-4 与缩臂阀 J1-21 不切（安全方向）。
- **ID 192 超时判故障**：>500 ms 未收到 ID 192 即视为故障态，同样切 J1-5/J1-18，**绝不把"收不到"等同于"未过卷"**。上电后收到第一帧 192 之前即为超时态。
- **超载切断**：已实现（与过卷同一切断输出），但默认关闭：`OVERLOAD_CUT_ENABLE 0`（`src/main.c` 顶部）。原因：P1/P2 未标定、无臂长/角度输入，力矩百分比算不出来，现在打开只会误切。待标定完成后再置 1。
- **强制开关（J1-7）/ 超载钥匙（J1-8）解除**：v1 未接入（无 DI 通道），待 DI 定位后随正式版加入。
- **主/副卷扬、配重阀、推杆、油冷/空调、蜂鸣器**：不在 v1 范围内，后续版本按文件 03 接入。

### 待用户定夺的分歧：文件 03 vs 文件 04

| 项目 | 文件 03（本版采用） | 文件 04 |
|---|---|---|
| 过卷切断范围 | 过卷切 J1-5 落幅 + J1-18 伸臂 | 只切对应钩的起钩阀 |
| 超载是否切缩臂 | 不切 J1-21（缩臂减小力矩，属安全方向） | 禁止缩臂 |

## 过卷信号：CAN ID 192（0xC0，臂头控制器 QH6546）

本车 J2-1/J2-2/J1-11 均为空脚，过卷与接近开关**不走模块 DI**，走 CAN：

| 字节 | 位（厂家 1-based 记位） | 含义 |
|---|---|---|
| byte1 | bit8（= 0x80） | 副钩过卷 |
| byte1 | bit7（= 0x40） | 主钩过卷 |
| byte4 | bit8（= 0x80） | 接近开关触发（v1 只记录，不参与切断） |

**位分配待实车核对**：厂家资料以 1-based 记位（bit8 = 最高位 0x80），代码按此实现并在注释中标明；实车合主令验证时若主/副钩切反，调换 `can_poll_rx()` 里两行的掩码即可。ID 192 周期 200 ms；其余 7 个字节内容未在资料中说明，v1 不解析。

## DI-HUNT 定位程序（v1 的唯一任务）

本板开关量靠 ADC 采样读回（只有 PE8–PE11 是纯数字输入），J1-6/J1-10 具体落在 8 槽×12 路矩阵的哪一格未知。v1 每秒扫一轮全矩阵，经 0x7A2 发出；同时 0x7A0 每 250 ms 汇报状态。

**做法（发动机熄火、钥匙 ON、刷 motion_ctrl v1）：**

1. 看 CAN 日志：0x7A0 字节 5 应为 `0xA5`（DI-HUNT 模式标志）；PA12 双闪（run 灯一闪一闪）；5 个阀脚对地电压应全为 0V（输出强制关断）。
2. 拨动**主令开关 J1-6**（闭合↔断开各停 2 秒以上）：看 0x7A2 矩阵里哪一格（槽号，通道号）跟着跳变（低→高，约 0→4000 或 0→某高值），记下 `(slot, ch)`。
3. 拨动**模式开关 J1-10**（变幅↔伸缩各停 2 秒以上）：同样记下跳变格 `(slot, ch)`。
4. 把两组数填入 `src/main.c` 顶部（见下节），重新编译，即为动作程序。

**0x7A2 格式（diag_mimic 同款）**：每秒 4 帧发一个槽的 12 路原始值，8 秒发完全部 8 个槽。字节 0–5：3 个通道原始值（u16 LE）；字节 6：高半字节=槽号（0–7），低半字节=帧序号（0–3，帧 f 装通道 3f、3f+1、3f+2）；字节 7：滚动计数。
**通道索引（kChans）**：0=PC3（ADC1 IN13）、1=PA6（IN6）、2=PC5（IN15）、3=PB0（IN8）、4=PB1（IN9）、5=PA7（IN7）、6=PA4（IN4）、7=PA5（IN5）、8=PC4（ADC2 IN14）、9=PC2（ADC2 IN12）、10=PC1（ADC3 IN11）、11=PC0（ADC3 IN10）。

**若拨动开关后没有任何一格跳变**：两个开关可能落在纯数字输入 PE8–PE11 上（ADC 扫不到），下一步需一个 GPIO IDR 扫描固件（读 GPIOE IDR 的 PE8–PE11 位），不要继续猜 ADC 通道。

#define DI_MASTER_SLOT  (1)     /* J1-6 主令开关：槽号，2026-11-12 实测 */
#define DI_MASTER_CH    (9)     /* J1-6 主令开关：kChans 索引 9=PC2，通 24V=4095、断开=7 */
#define DI_MODE_SLOT    (3)     /* J1-10 变幅/伸缩切换：槽号，2026-11-12 实测 */

`DI_HIGH_RAW 2048` 为判高阈值（半量程暂定）；HUNT 实测出开关高/低电平的真实原始值后，按实测校准。`DI_MODE_INVERT` 默认 0（J1-10 高=伸缩）；若实测相反改成 1。

## 诊断帧

### 0x7A0 状态帧（每 250 ms）

| 字节 | 内容 |
|---|---|
| 0–3 | ms 计数（LE） |
| 4 | 滚动计数 |
| 5 | 模式标志（见下表） |
| 6–7 | 本轮全矩阵最大值（LE，diag_mimic 同款） |

**字节 5 编码**：

| 位 | 含义 |
|---|---|
| bit7 | DI 未确认：1 = DI-HUNT 模式（输出强制关断），0 = 动作模式 |
| bit6 | ID 192 超时故障（>500 ms 未收到） |
| bit5 | 过卷有效（主钩或副钩任一） |
| bit4 | 主令 ON（J1-6 闭合；HUNT 模式下恒 0） |
| bit3 | 伸缩模式（1=伸缩/J1-10 高，0=变幅；HUNT 模式下恒 0） |
| bit2 | 超载切断有效（v1 恒 0，`OVERLOAD_CUT_ENABLE=0`） |
| bit1–0 | 保留 0 |

HUNT 模式基值 `0xA5`、动作模式基值 `0x25`（bit7 为模式位：1=HUNT、0=动作；低 3 位 101 为"存活签名"，与 diag_mimic 系固件一致），典型值：HUNT 正常 `0xA5`、HUNT 且 ID 192 超时 `0xE5`、HUNT 且过卷 `0xB5`；动作模式主令 ON、变幅 `0x27`。

### 0x7A2 矩阵组帧（每秒 4 帧）

见"DI-HUNT 定位程序"一节。

## 构建

```sh
./build.sh
```

- 有 `arm-none-eabi-gcc` 的机器上：CMake 交叉编译，产物 `build/dl1824.bin`，自动填充 0xFF 至 **189,551 字节**，头 8 字节自检应为 `38 65 00 20 …`（栈顶 0x20006538 小端 + 0x0801xxxx 奇数复位地址）。
- 无交叉工具链的机器上：只做宿主 cc 严格语法检查（`-Werror=implicit-function-declaration -Werror=implicit-int`），不产生可刷 bin。

链接脚本 `STM32F407VE_APP.ld` 与 freq_demo 同款：FLASH 基址 0x08010000（前 64 KB 让给原厂 Bootloader），`_estack = 0x20006538`（与原厂 dl1824.bin 初始栈值一致）。芯片型号确认后只需改链接脚本的 ORIGIN/LENGTH 与启动代码的 RAM 顶。

## 实车验证（发动机熄火、钥匙 ON）

**DI-HUNT 模式（v1 当前状态）**：刷入后 5 个阀脚应全为 0V（万用表对地量 J1-2/J1-4/J1-5/J1-18/J1-21）；PA12 双闪；0x7A0 字节 5 为 0xA5；按"HUNT 定位程序"拨动两个开关并记录跳变格。

**DI 填入后的动作模式**：

1. 主令 J1-6 闭合 → J1-2（主控阀）跳 24V，可听到阀"咔哒"吸合；断开 → 回 0V。
2. 变幅模式（J1-10 低）+ 主令 ON → J1-4、J1-5 跳 24V，J1-18、J1-21 为 0V。
3. 拨到伸缩模式（J1-10 高）+ 主令 ON → J1-18、J1-21 跳 24V，J1-4、J1-5 回 0V。
4. 过卷验证：需 QH6546 在线；模拟过卷（或断开 ID 192 超过 500 ms）→ J1-5、J1-18 应切断回 0V，J1-4、J1-21 不受影响。

**安全**：验证全程发动机熄火（液压泵不转，阀只吸合不动作）；吊臂下严禁站人；发现异响/异味/异常发热立即断电。首次上车只验证得电/失电（万用表 + 听阀响），不带载动作。
