# demo_blink：电压控制闪灯演示固件（DL-IO1824G 台架）

基于 diag_mimic v4（打包基线、时钟归一化、全矩阵遥测、Bus-Off 自恢复、
ADC 480 周期采样）扩展。演示目标（2026-11-11 用户定）：灯接 J1-17，
闪烁分 8 个明显档位，输入电压越大、闪频越高。

## 两种模式

- **轮扫模式（上电默认）**：与 diag 相同——轮始齐闪 3 次标记，45 脚逐个
  点亮 1 秒；遥测帧 0x7A0/0x7A1/0x7A2 格式同 diag_mimic README。
- **演示模式**：用 CAN 工具发一帧 **0x7FF** 切换：
  - 数据字节 0 = **步号 1~45** → 该步引脚即灯，立即进入演示；
  - 数据字节 0 = **0** → 退回轮扫模式。
  找步号的方法：轮扫时盯住 J1-17 的灯亮瞬间，读 0x7A0 字节 5（即步号），
  或按“灯亮在齐闪标记后第 N 秒”估算；发 0x7FF 选定后可反复改选、不用重刷。

## 演示规则（v5：连续变频，用户定版）

- 输出 = 选定引脚的 PWM（高电平 24V 来自负载电源），占空比 50%；
- 输入 =（槽 0，PC2）原始计数（AI 信号接 J1-12），每 200ms 采样一轮；
- **频率律：0V → 频率 0（长亮不闪）；电压越高频率越高；24V → 20Hz**，
  线性连续变化（不是分档）；原始计数 <=40 视为 0V；
- `RAW_AT_24V` = 24V 对应的原始计数，暂定 4000（近满量程，**待标定**：
  实测 24V 时的原始值后改 main_demo.c 这一行即可）；
- 演示模式下 0x7A0：字节 5 = 当前频率 Hz（0 = 长亮），字节 6-7 = 输入原始值。

## 已知边界

- 闪烁时间粒度 = 主循环 10ms：10Hz 档相位略粗，演示足够；
- CAN 接收走 FIFO0 轮询（过滤器为全通）；若命令无响应先确认工具能正常
  发送（正常模式、非监听）；
- 输入通路（J1-12→槽0/PC2）以原厂固件通道表为据；若实测档位不跟随，
  用 0x7A2 全矩阵继续定位（方法同 diag_mimic README）。

## v4（2026-11-11）：命令接收加固 + 应答帧

背景：v3 台架反馈“发了 0x7FF 灯仍间隔闪”——实为命令未被接收、固件一直
停在轮扫模式。v4 三处加固：

1. 接收轮询两个 FIFO（FIFO0/FIFO1），且**标准帧、扩展帧都认**（工具若误发
   扩展帧的 0x7FF 也能进）；
2. **应答帧 0x7A3**：收到并执行命令后立即回一帧（字节0=命令值、字节1=档位、
   字节2=固件版本 4）。监听里看到 0x7A3 = 命令确实进了控制器；看不到 =
   命令没发到（查工具发送设置：ID 用十六进制 7FF、数据字节0=步号）；
3. 预留 `LAMP_DEFAULT_STEP` 宏：填步号后上电直进演示（免命令版），
   默认 0=上电轮扫。
