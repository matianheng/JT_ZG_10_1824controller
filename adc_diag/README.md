# adc_diag — P1/P2 压力 ADC 诊断工程（2026-11-14）

底本：motion_ctrl v2.11（提交 d5068ef）原样复制，**v2.11 本身不动，main 分支不动**。四个试验版各为一个独立子目录，每版只改一处，按顺序逐个刷、逐个录日志，找到哪步就停。

## 四个版本（按测试顺序）

| 顺序 | 目录 | 改动 | 判据（0x7A2 / 0x7A0） |
|---|---|---|---|
| 1 | `diag_b/` | 长沉降：`main.c` 731、744 行 `delay_us(1000)` → `delay_ms(50)` | 矩阵里出现 600–1000 区间的格，或有格跟臂动 |
| 2 | `diag_c/` | PA15 翻转：`main.c` 777–778 行 PA15 置高 → 置低 | 同上（PA15 若为第 4 位选通/使能，P1/P2 可能在槽 8–15） |
| 3 | `diag_d1/` | 选通线回读：`main.c` 196 行补 IDR 宏，946 行 0x7A0 d[7] 改发 `(IDR(GPIOE_BASE)>>12)&7` | 0x7A0 d[7] 在 0–7 间循环变化 = 选通线物理上在变；恒定/全 0 = mux 没切换 |
| 4 | `diag_d2/` | 45 脚全置高：`main.c` 451–455 行新增 `all_outputs_high()`，881、893 行两处调用替换 | 矩阵里出现 600–1000 区间的格；若出现，再逐脚二分是哪根使能脚 |

## 用户操作（每版相同）

```sh
git fetch origin && git checkout adc-diag && git pull
cd adc_diag/diag_b        # 换成要测的版本目录
./build.sh
```

核对：`build/dl1824.bin` = **189551 字节**、头字节 `38 65 00 20`。用厂家刷机工具刷入，刷后：

- 发动机可熄火，不用动臂（做一次全行程起/趴臂更好，但不是必需）。
- 录 CAN 日志 **30 秒以上**，发回 .asc。
- diag_d2 安全注意：45 脚全置高，配重/推杆/油冷/空调继电器/蜂鸣器可能得电；**必须发动机熄火、不推手柄、臂放低、空钩、臂下无人**；J1-3 本车未接线，无物理动作。9 个已确认阀按 v2.11 逻辑重写，动作行为与 v2.11 相同。

## 背景（为什么做这四个）

- 原厂能正常读 P1/P2（趴到底 P1 AD=657、P2 AD=598；10.3° 时 P1=876、P2=575；最高 81.2° 时 P1=969、P2=597；零值 575=0MPa、满值 2012=25MPa，57.48 counts/MPa）。
- 我程序 v2.11 的 0x7A2 全矩阵 96 格在全行程起/趴臂时最大只变 40 个数，P1 应变约 312–500 个数——**P1 确定不在矩阵里**；代码认的 PC2 是数字开关不是压力通道。
- 详见 `../P1_P2_ADC_诊断报告_2026-11-14.md`。
